# CI/CD SberAct

Workflow .github/workflows/windows.yml подготовлен для стандартных GitHub-hosted
Windows runner. Личный ПК для его выполнения не нужен.
Первоначальное подключение: [CI-CLOUD.md](CI-CLOUD.md).

## Процесс

| Событие | Результат |
|---|---|
| Push release, PR в release/main | Обязательные проверки Node/frontend и всего backend |
| PR release → main | Дополнительно новая версия относительно main |
| Push main | Проверки, сборка приложения, полный OCR-комплект и черновик Release |
| Ручной запуск release/main | Проверки; сборка только для main |

Версия и CHANGELOG готовятся вручную в release.
GitHub не создаёт коммитов и не сливает ветки.
Задание выпуска создаёт черновик Release vX.Y.Z на проверенном коммите main;
если тега ещё нет, он создаётся через API GitHub. Опубликованные выпуски,
теги другого коммита и чужие черновики не перезаписываются.
Черновик публикуется пользователем после ручной проверки.

## Проверки и сборка

Repository policy отклоняет внешние fork и PR в main не из release.
Windows checks выполняет CI-тесты, TypeScript, весь frontend, диагностику,
обновление и установщик. Backend checks устанавливает версии из
requirements-ci.lock, собирает и загружает модель, получает закреплённый
корпус и запускает весь backend с --require-golden-corpus.

Build Windows installer зависит от обоих проверочных заданий.
Complete offline package скачивает готовый OCR частями, проверяет SHA-256
всех файлов ZIP и сохраняет черновик Release. Использованные части удаляются
по мере объединения; публикация читает диапазоны общего ZIP без новых копий.
Каждое задание получает отдельный windows-2022.

## Малое и полное обновление

Для уже установленного приложения скачивается только
SberAct-App-Update-X.Y.Z.zip. Распаковать его и выбрать полученную папку
в приложении. Манифест малого комплекта имеет converter=null:
установленный OCR сохраняется.

Для первой установки или замены OCR нужны установщик, latest.yml, blockmap,
update-package.json, converter-manifest.json, ocr-assets.json, части
converter.zip.part-* и Assemble-Update.ps1 из полного выпуска.
Сложить их в отдельную папку SberAct-Update и выполнить в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Assemble-Update.ps1
```

Полученный converter.zip проверяется по SHA-256. Папку можно выбрать
в приложении для обновления либо запустить установщик для первой установки.
Малый ZIP для полного комплекта дополнительно скачивать не нужно.
При изменении OCR пока скачивается весь модуль. Файловые дельты отложены
на следующий этап после проверки облачной схемы.

## Источники и доступ

Корпус: private Andrew09127/data-for-verification-CI-CD,
коммит 29930862660b3da94c7c477789ceef30a6b968e7.
Readonly deploy key хранится в CI_DATA_SSH_KEY. Коммит и имя репозитория
закреплены в private-data.json и workflow; тест проверяет согласованность.
Состав и SHA корпуса проверяются по assets.lock.json.

Модель backend уже хранится частями в основном Git-репозитории.
check-model.py собирает и проверяет её, не допускает тихих skip при отсутствии.
OCR хранится в опубликованном техническом Release ci-ocr-7dc90fd871184668.
Описание и SHA частей закреплены в scripts/ci/ocr-assets.json.

## Приватность, результаты и стоимость

Оригиналы закрытого корпуса, сгенерированные по ним акты, XML и сырой вывод
backend-тестов не публикуются как артефакты или журналы Actions.
private-tests.py сохраняет вывод во временной VM и показывает только
passed/failed/skipped. Подробности воспроизводятся локально с тем же корпусом.

Между заданиями передаются только сборка frontend и компонент приложения,
retention-days=1. Постоянный результат находится в GitHub Releases.
Standard runner публичного репозитория бесплатен; Actions artifact storage
имеет отдельную общую квоту. Настройки Billing нужно проверить, если требуется
полностью запретить платное превышение.

Первый настоящий Actions run обязателен: локальные проверки не подтверждают
доступ к secret, доступность пакетов и дисковый бюджет чистого runner.
После него для main включаются Require PR и обязательные Repository policy,
Windows checks, Backend checks.

Локальные export-инструменты и данные в C:\Диск D\Сбер\SberAct-CI сохранены.
Cloud workflow не использует локальные пути. Все подготовленные на ПК папки
остаются внутри C:\Диск D\Сбер.

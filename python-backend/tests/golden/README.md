# Golden-master — сеть безопасности для рефакторинга

Фиксирует ПОЛНОЕ поведение `DocumentAnalyzer.analyze()` на всём корпусе
`Заявления/` (67 документов). Назначение — рефакторить гигантские функции
бэкенда **без регрессий**: вывод обязан остаться побайтово прежним.

## Файлы
- `_snapshot.py` — детерминированная сериализация результата `analyze()`
  (поля, обязательства, залоги, должники, 3-и лица, рекомендованные акты, тип/
  уверенность; для `rawText` — длина + sha256). Общий код для генератора и теста.
- `golden_master.json` — зафиксированный эталон (по одному снимку на документ).
- `test_golden_master.py` — pytest: текущий `analyze()` == эталон, для каждого файла.
- `regenerate_golden.py` — **ручной** генератор эталона.

## Рабочий цикл

### Структурный рефакторинг (разбиение функций, вынос модулей)
Поведение НЕ меняется. Эталон НЕ трогаем.
```
venv/Scripts/python.exe -m pytest tests/golden/ -q
```
Зелено → регрессий нет. Красно → регрессия, чинить (не регенерировать!).

### Намеренное изменение поведения (удаление хардкода, улучшение анализа)
1. Внести изменение.
2. Прогнать сверку — увидеть, КАКИЕ снимки изменились (это и есть эффект правки).
3. Вручную убедиться, что новый вывод корректнее эталонного.
4. Только тогда осознанно перегенерировать эталон:
   ```
   venv/Scripts/python.exe tests/golden/regenerate_golden.py
   ```
5. Закоммитить новый `golden_master.json` вместе с правкой.

## Гарантии
- `analyze()` детерминирован (проверено: два прогона дают идентичный JSON).
- Сеть доказанно ловит регрессии (контролируемая мутация → краснеют ровно
  затронутые снимки).
- Документы вне репозитория → тесты `skip` (см. `skipif`), CI не падает.
